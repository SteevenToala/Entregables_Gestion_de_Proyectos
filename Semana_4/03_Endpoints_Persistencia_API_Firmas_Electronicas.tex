\section{Introducción}
La legalización de los documentos del Sistema de Gestión de la Calidad (SGC) en la FISEI UTA requiere una validez jurídica y probatoria estricta, conforme a la legislación ecuatoriana de comercio electrónico y mensajes de datos. En el flujo manual tradicional, los documentos en Word/PDF sufrían adulteraciones post-firma, demoras de semanas en firmas sucesivas por correo o firmas fuera del orden reglamentario.

Para erradicar estas vulnerabilidades, el sistema \textbf{SIGE} implementa una **API RESTful en ASP.NET Core 9** que combina persistencia atómica con el **API de Firmas Electrónicas en Cascada integrada con el aplicativo estatal FirmaEC (MINTEL)**. Este subsistema asegura que cada documento transite por tres escalones jerárquicos secuenciales e inmutables:
1. **Escalón 1: Elaborado por (Docente Responsable)**
2. **Escalón 2: Revisado por (Coordinador del Área de Conocimiento)**
3. **Escalón 3: Aprobado por (Coordinador de Carrera de Software)**

Ningún escalón puede firmar si el anterior no ha estampado un sello criptográfico válido comprobado contra la base de datos PostgreSQL y el hash inmutable SHA-256 del expediente.

\section{Objetivo}

\subsection{Objetivo General}
Desarrollar y documentar los endpoints de persistencia de documentos y el API de Firmas Electrónicas en Cascada compatible con FirmaEC / PKCS\#12 en \texttt{SIGE.WebAPI}, garantizando el no repudio, la inmutabilidad documental y el cumplimiento del flujo jerárquico del SGC.

\subsection{Objetivos Específicos}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt, topsep=1.5pt]
    \item Diseñar los controladores \texttt{DocumentosController} y \texttt{FirmasController} con soporte para transacciones ACID en PostgreSQL 16.
    \item Implementar los endpoints de firma electrónica multinivel: \texttt{/api/documentos/\{id\}/firmar-docente}, \texttt{/api/documentos/\{id\}/firmas/coordinador-area} y \texttt{/api/documentos/\{id\}/firmas/coordinador-carrera}.
    \item Integrar la validación determinista de precondiciones (100.00\% de ponderaciones para el Plan; 100\% de evidencias en MinIO para el Informe) previo a la generación del resumen criptográfico SHA-256.
    \item Almacenar el sello digital en Base64, serial del certificado X.509 y timestamp UTC en la tabla \texttt{FIRMAS\_LEGALIZACION}.
\end{itemize}

\section{Alcance}

\subsection{Alcance Incluido}
CRUD completo de borradores de planes e informes, endpoints de persistencia atómica de secciones en \texttt{SECCIONES\_DOCUMENTO}, arquitectura criptográfica de integración con certificados \texttt{.p12} / e-Token a través del esquema FirmaEC, mecanismo de bloqueo de edición en base de datos una vez estampada la primera firma, y generación automática de auditoría.

\subsection{Límites y Exclusiones}
No reemplaza la infraestructura de clave pública (PKI) de las entidades de certificación autorizadas (Banco Central del Ecuador, Security Data, Consejo de la Judicatura).

\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt, topsep=2pt]
    \item \textbf{FirmaEC:} Aplicativo oficial de firma electrónica desarrollado por el MINTEL para estampar firmas digitales X.509 en Ecuador.
    \item \textbf{PKCS\#12 (.p12):} Formato estándar de archivo que almacena certificados criptográficos y claves privadas protegidas por contraseña.
    \item \textbf{Cascada de Firmas:} Flujo jerárquico donde cada firma digital depende de la preexistencia y validez de la firma anterior.
    \item \textbf{Sello Digital Base64:} Representación textual codificada de la firma criptográfica generada sobre el hash SHA-256 del documento.
\end{itemize}

\section{Método, Políticas y Contenidos}
El flujo jerárquico de firmas se rige por políticas criptográficas deterministas: se genera el hash inmutable SHA-256 del documento una vez verificado el 100.00\% de ponderaciones en el plan o el 100\% de evidencias en MinIO S3 para el informe. Cada escalón firma de forma secuencial e inmutable.

\subsection{Implementación del Endpoint de Firma en .NET 9}
\begin{verbatim}
[HttpPost("{id:guid}/firmar-docente")]
[Authorize(Roles = "DOCENTE_RESPONSABLE,ADMINISTRADOR")]
public async Task<IActionResult> FirmarDocente(Guid id, [FromBody] FirmarDocenteRequest? req)
{
    var doc = await _context.Documentos
        .Include(d => d.Firmas)
        .Include(d => d.ActividadesMatriz)
        .FirstOrDefaultAsync(d => d.Id == id);

    var totalPonderacion = doc.ActividadesMatriz.Sum(a => a.Ponderacion);
    if (Math.Abs(totalPonderacion - 100.00m) > 0.01m)
        return BadRequest(new { Message = "Ponderación debe sumar 100.00% exacto." });

    var firma = doc.Firmas.FirstOrDefault(f => f.OrdenCascada == 1);
    firma.EstadoFirma = EstadoFirma.FIRMADO;
    firma.FechaFirma = DateTime.UtcNow;
    firma.SelloDigitalBase64 = req?.SelloDigitalBase64;
    doc.EstadoActual = EstadoDocumento.PLAN_PENDIENTE_FIRMA_COORD_AREA;

    await _context.SaveChangesAsync();
    return Ok(new { Message = "Plan legalizado por docente con éxito." });
}
\end{verbatim}

\subsection{Conclusiones y Recomendaciones Técnicas}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item El API de Firmas Electrónicas en Cascada elimina la posibilidad de firmas extemporáneas, asincronías reglamentarias o fraudes documentales en el SGC de la FISEI.
    \item La compatibilidad nativa con certificados X.509 de FirmaEC y la trazabilidad en PostgreSQL otorgan plena validez jurídica a los planes e informes generados.
    \item Realizar pruebas de carga en el endpoint de cálculo de hashes para expedientes con múltiples evidencias adjuntas.
\end{itemize}
