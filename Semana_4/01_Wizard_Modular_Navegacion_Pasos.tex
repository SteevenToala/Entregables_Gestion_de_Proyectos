% =============================================================
% 2. INTRODUCCIÓN
% =============================================================
\section{Introducción}
Los formatos institucionales del Sistema de Gestión de Calidad (SGC) de la FISEI UTA (\texttt{UTA-SGC-A-2-1-P7-T1} para el Plan de Trabajo e \texttt{UTA-SGC-A-2-1-P7-T2} para el Informe de Cumplimiento) se componen de múltiples secciones secuenciales: Datos Informativos, Justificación/Objetivos, Matriz Cronograma de Actividades, Anexos/Evidencias y Circuito de Firmas. La presentación de estos extensos formularios en una sola vista monolítica satura al usuario y propicia la pérdida involuntaria de datos.

Para resolver esta problemática de interacción, se diseñó e implementó un componente asistido por pasos (\textbf{Wizard Modular}) en \textbf{React + Vite} y \textbf{Tailwind CSS}. Este asistente divide el proceso de llenado en pestañas lógicas conectadas, valida los requisitos mínimos de cada etapa antes de permitir la navegación, proporciona un indicador de avance porcentual en tiempo real y gestiona el estado transaccional del expediente con soporte para microanimaciones CSS Keyframes.

% =============================================================
% 3. OBJETIVO
% =============================================================
\section{Objetivo}

\subsection{Objetivo General}
Desarrollar el componente de interfaz \texttt{PlanEditorWizard.jsx} bajo la arquitectura de pestañas modulares en React y Vite, guiando al docente en el llenado guiado y secuencial de su planificación semestral conforme al formato oficial del SGC de la FISEI UTA.

\subsection{Objetivos Específicos}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt, topsep=1.5pt]
    \item Diseñar la barra de navegación por pasos con estados visuales claros: \textit{Completado}, \textit{En Edición}, \textit{Pendiente} y \textit{Bloqueado}, aplicando los colores institucionales (\texttt{\#00345E}).
    \item Implementar validaciones deterministas de salida en cada pestaña (Validation Gates que impiden avanzar si faltan campos obligatorios).
    \item Integrar el cálculo reactivo del porcentaje de completitud global del expediente.
    \item Conectar el Wizard con el cliente Axios institucional con auto-renovación de tokens y el backend Node.js + Express (v5).
\end{itemize}

% 5. DEFINICIONES
% =============================================================
\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt, topsep=2pt]
    \item \textbf{Wizard Pattern:} Patrón de diseño de interfaz que descompone una tarea compleja en pasos secuenciales y validados.
    \item \textbf{Validation Gate:} Condición de negocio que restringe el paso a la siguiente etapa hasta satisfacer los requisitos de calidad.
    \item \textbf{EDT (\textit{Estructura de Desglose del Trabajo}):} Descomposición funcional jerárquica de entregables del proyecto.
\end{itemize}

\section{Método, Políticas y Contenidos}
Construcción de componentes funcionales modulares en React con Hooks nativos y Tailwind CSS. Se establecen políticas rigurosas de navegación:
\begin{enumerate}[leftmargin=1.5em, itemsep=1.5pt]
    \item El docente puede regresar libremente a pasos anteriores guardados.
    \item Se bloquea el botón "Siguiente" si el paso actual no satisface la totalidad de validaciones requeridas.
    \item La pestaña de firmas permanece bloqueada hasta que la matriz de ponderación cierre con exactitud en el 100.00\%.
\end{enumerate}

\section{Descripción de actividades}

\subsection{Estructura de Pasos del Wizard (PlanEditorWizard.jsx)}
\begin{lstlisting}[language=Java]
// frontend/src/pages/PlanEditorWizard.jsx
export const WIZARD_STEPS = [
  { id: 1, key: 'datos', label: '1. Datos Informativos', icon: 'FileText' },
  { id: 2, key: 'justificacion', label: '2. Justificacion y Objetivos', icon: 'Target' },
  { id: 3, key: 'matriz', label: '3. Matriz Cronograma (100%)', icon: 'Table' },
  { id: 4, key: 'evidencias', label: '4. Anexos y Evidencias', icon: 'Paperclip' },
  { id: 5, key: 'firmas', label: '5. Cascada de Firmas', icon: 'CheckSquare' }
];
\end{lstlisting}

\subsection{Flujo de Validación y Completitud Reactiva}
El avance porcentual se calcula reactivamente en memoria:
\begin{equation}
\text{Progreso Global} = \frac{\sum_{i=1}^{5} \text{PuntajePaso}_i}{5} \times 100\%
\end{equation}
Si el docente intenta acceder a la pestaña de Firmas sin alcanzar el 100\% de ponderación en la Matriz, la interfaz despliega una alerta modal bloqueante con la advertencia de Validation Gate.

\subsection{Conclusiones y Recomendaciones Técnicas}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item El Wizard modular elimina la fatiga cognitiva del docente frente a formularios largos, guiándolo paso a paso y reduciendo los rechazos por omisión de requisitos.
    \item La arquitectura por componentes facilita la reutilización inmediata tanto para planes de trabajo como para informes finales de cumplimiento.
    \item Se recomienda articular el Wizard con el motor de autoguardado periódico TipTap (EDT 4.2) para brindar resiliencia absoluta ante caídas de red.
\end{itemize}
