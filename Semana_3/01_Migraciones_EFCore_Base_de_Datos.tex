\section{Título}
\textbf{Denominación del Entregable:} Implementación de Tablas, Índices y Scripts DDL en PostgreSQL 18 (Node.js / Express v5) (EDT 3.1)



\section{Introducción}
En la transición del diseño relacional a la fase de construcción del sistema \textbf{SIGE}, la capa de persistencia requiere materializar el modelo lógico en el motor relacional \textbf{PostgreSQL (18)}. Se implementa una arquitectura basada en scripts DDL deterministas (\texttt{schema.sql}), ejecución automatizada mediante el script de arranque \texttt{init.js} en Node.js y gestión de transacciones de alto rendimiento mediante el connection pool de la librería oficial \texttt{pg} (\texttt{backend/src/config/db.js}).

Este documento detalla la implementación técnica del esquema físico en PostgreSQL 18, la creación de las tablas relacionales con soporte UUID v4 nativo (\texttt{gen\_random\_uuid()}), restricciones de integridad \texttt{CHECK}, índices compuestos optimizados y pruebas de concurrencia ACID para el ciclo de vida documental del Sistema de Gestión de Calidad (SGC).

\section{Objetivo}

\subsection{Objetivo General}
Implementar el modelo relacional físico en PostgreSQL 18 mediante scripts DDL deterministas y el pool de conexiones en Node.js + Express (v5), estableciendo esquemas normalizados en 3FN, índices de rendimiento y restricciones de integridad para el ciclo de vida documental del SGC.

\subsection{Objetivos Específicos}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt, topsep=1.5pt]
    \item Diseñar y parametrizar el script DDL \texttt{schema.sql} para la creación de las tablas relacionales con tipos UUID, timestamps UTC e integridad referencial.
    \item Configurar el módulo \texttt{backend/src/config/db.js} con connection pool \texttt{pg.Pool} optimizado para peticiones concurrentes.
    \item Desarrollar el script de inicialización \texttt{backend/src/database/init.js} para la creación desatendida del esquema en entornos locales y contenedores.
    \item Implementar índices B-Tree únicos y compuestos para la auditoría inmutable, control de plazos extemporáneos y circuito secuencial de firmas en cascada.
\end{itemize}

\section{Alcance}

\subsection{Alcance Incluido}
Mapeo de entidades: \texttt{carreras\_unidades}, \texttt{usuarios}, \texttt{roles}, \texttt{auth\_tokens}, \texttt{catalogo\_actividades}, \texttt{documentos}, \texttt{secciones\_documento}, \texttt{habilitaciones\_extemporaneas}, \texttt{solicitudes\_modificacion\_plan}, \texttt{actividades\_matriz}, \texttt{evidencias\_minio}, \texttt{firmas\_legalizacion}, \texttt{observaciones\_comite}, \texttt{historial\_cambios} y \texttt{auditoria\_logs}. Restricciones \texttt{CHECK} para ponderaciones y orden de firmas (1, 2, 3).

\subsection{Límites y Exclusiones}
No incluye el servicio de almacenamiento de blobs binarios (delegado a MinIO en EDT 3.11) ni la capa de consultas OLAP.

\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item \textbf{PostgreSQL 18:} Motor de base de datos relacional de código abierto que ofrece transacciones ACID y alto rendimiento.
    \item \textbf{Connection Pool (\texttt{pg.Pool}):} Mecanismo de reuso de conexiones TCP abiertas hacia PostgreSQL para reducir la latencia de handshake.
    \item \textbf{Script DDL (\textit{Data Definition Language}):} Conjunto de sentencias SQL que estructuran el almacenamiento relacional.
    \item \textbf{EDT (\textit{Estructura de Desglose del Trabajo}):} Descomposición jerárquica del proyecto orientada a entregables verificables.
\end{itemize}

\section{Método, Políticas y Contenidos}

\subsection{Metodología}
Construcción directa y modular de scripts SQL parametrizados ejecutados mediante el driver nativo \texttt{pg} en Node.js, integrados en el ciclo de vida del contenedor Docker \texttt{sige-postgres}.

\subsection{Políticas de Persistencia}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt]
    \item Toda tabla contiene clave primaria UUID inmutable y columnas de trazabilidad temporal (\texttt{created\_at} con \texttt{DEFAULT CURRENT\_TIMESTAMP}).
    \item Se prohíbe el borrado físico (\texttt{CASCADE}) en tablas transaccionales de auditoría, firmas y documentos legalizados.
\end{itemize}

\section{Descripción de actividades}

\subsection{Estructura de Persistencia en \texttt{backend/src/database/schema.sql}}
A continuación se ilustra la definición SQL de la tabla de firmas en cascada y sus índices únicos:

\begin{lstlisting}[language=SQL]
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

CREATE TABLE IF NOT EXISTS firmas_legalizacion (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    documento_id UUID NOT NULL REFERENCES documentos(id) ON DELETE RESTRICT,
    usuario_firmante_id UUID NOT NULL REFERENCES usuarios(id) ON DELETE RESTRICT,
    fase_documento VARCHAR(30) NOT NULL CHECK (fase_documento IN ('PLANIFICACION_INICIAL', 'INFORME_FINAL')),
    orden_cascada INT NOT NULL CHECK (orden_cascada IN (1, 2, 3)),
    rol_instancia VARCHAR(40) NOT NULL CHECK (rol_instancia IN ('DOCENTE_RESPONSABLE', 'COORD_AREA_CONOCIMIENTO', 'COORD_CARRERA')),
    estado_firma VARCHAR(20) NOT NULL DEFAULT 'PENDIENTE' CHECK (estado_firma IN ('PENDIENTE', 'FIRMADO', 'RECHAZADO')),
    serial_certificado VARCHAR(150),
    fecha_firma TIMESTAMP WITH TIME ZONE,
    sello_digital_base64 TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Restriccion de unicidad estricta para la cascada jerarquica
CREATE UNIQUE INDEX IF NOT EXISTS uq_firmas_documento_fase_orden 
ON firmas_legalizacion(documento_id, fase_documento, orden_cascada);
\end{lstlisting}

\subsection{Script de Inicialización Automatizada (\texttt{init.js})}
\begin{lstlisting}[language=Java]
// backend/src/database/init.js
import fs from 'fs';
import path from 'path';
import { fileURLToPath } from 'url';
import pool from '../config/db.js';

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

export const initializeDatabase = async () => {
  try {
    const schemaPath = path.join(__dirname, 'schema.sql');
    const schemaSql = fs.readFileSync(schemaPath, 'utf-8');
    await pool.query(schemaSql);
    console.log('PostgreSQL 18: Esquema DDL inicializado exitosamente.');
  } catch (error) {
    console.error('Error al inicializar esquema PostgreSQL 18:', error.message);
    throw error;
  }
};
\end{lstlisting}
