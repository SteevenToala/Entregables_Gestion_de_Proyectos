\section{Introducción}
En la transición del diseño relacional a la fase de construcción del sistema \textbf{SIGE}, la capa de infraestructura requiere materializar el modelo lógico en el motor de base de datos relacional **PostgreSQL 16**. El uso de **Entity Framework Core 9 (EF Core)** bajo el enfoque *Code-First* garantiza el mapeo fuertemente tipado de las entidades del dominio hacia el esquema físico, el control riguroso de migraciones versionadas y la definición imperativa de restricciones de integridad, índices únicos y reglas de cascada mediante la API fluida (*Fluent API*).

Este documento detalla la implementación técnica de las migraciones iniciales en el ensamblado \texttt{SIGE.Infrastructure}, el mapeo de las 13 entidades transaccionales (con especial énfasis en \texttt{DOCUMENTOS}, \texttt{ACTIVIDADES\_MATRIZ} y \texttt{FIRMAS\_LEGALIZACION}) y las pruebas de consistencia relacional ejecutadas.

\section{Objetivo}

\subsection{Objetivo General}
Implementar el modelo relacional físico en PostgreSQL 16 mediante Entity Framework Core 9 en la solución .NET 9, estableciendo esquemas normalizados, índices de rendimiento y restricciones de integridad para el ciclo de vida documental del SGC.

\subsection{Objetivos Específicos}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt, topsep=1.5pt]
    \item Configurar el contexto de persistencia \texttt{ApplicationDbContext} con *Fluent API* para mapear las 13 entidades del dominio.
    \item Generar y aplicar las migraciones iniciales garantizando tipos nativos UUID (\texttt{uuid-ossp}), timestamps con zona horaria e integridad referencial estricta.
    \item Implementar índices compuestos únicos para la auditoría, control extemporáneo y el circuito secuencial de firmas.
\end{itemize}

\section{Alcance}

\subsection{Alcance Incluido}
Mapeo de entidades: \texttt{CarreraUnidad}, \texttt{Usuario}, \texttt{CatalogoActividad}, \texttt{Documento}, \texttt{SeccionDocumento}, \texttt{HabilitacionExtemporanea}, \texttt{SolicitudModificacionPlan}, \texttt{ActividadMatriz}, \texttt{EvidenciaMinio}, \texttt{FirmaLegalizacion}, \texttt{ObservacionComite}, \texttt{HistorialCambio} y \texttt{LogAuditoria}. Restricciones \texttt{CHECK} para ponderaciones y orden de firmas.

\subsection{Límites y Exclusiones}
No incluye el servicio de almacenamiento de blobs binarios (delegado a MinIO en EDT 3.11).

\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt, topsep=2pt]
    \item \textbf{Code-First:} Enfoque de ORM donde las clases de entidad en C\# definen la estructura de la base de datos relacional.
    \item \textbf{Fluent API:} Mecanismo programático en EF Core para configurar mapeos que sobrepasan las anotaciones de datos simples.
    \item \textbf{Migración:} Script de evolución incremental de esquema que permite versionar y replicar cambios en entornos de desarrollo y producción.
\end{itemize}

\section{Descripción de actividades}

\subsection{Configuración de Fluent API en ApplicationDbContext}
Se implementó el mapeo estricto de las 13 entidades en el ensamblado \texttt{SIGE.Infrastructure}. A nivel de base de datos se aseguró que ninguna firma pueda duplicarse para la misma fase y posición de orden jerárquico mediante la restricción única:
\begin{verbatim}
builder.Entity<FirmaLegalizacion>(entity =>
{
    entity.ToTable("FIRMAS_LEGALIZACION");
    entity.HasKey(e => e.Id);
    entity.Property(e => e.Id).HasDefaultValueSql("gen_random_uuid()");
    entity.Property(e => e.FaseDocumento).HasMaxLength(30).IsRequired();
    entity.Property(e => e.OrdenCascada).IsRequired();
    entity.HasIndex(e => new { e.DocumentoId, e.FaseDocumento, e.OrdenCascada })
          .IsUnique()
          .HasDatabaseName("uq_firmas_documento_fase_orden");
});
\end{verbatim}

\subsection{Generación y Ejecución de la Migración}
Se ejecutaron satisfactoriamente los comandos de migración sin inconsistencias:
\begin{enumerate}[leftmargin=1.5em, itemsep=2pt]
    \item \texttt{dotnet ef migrations add InitialCreate\_Postgres16 --project src/SIGE.Infrastructure --startup-project src/SIGE.WebAPI}
    \item \texttt{dotnet ef database update --project src/SIGE.Infrastructure --startup-project src/SIGE.WebAPI}
\end{enumerate}

\subsection{Verificación de Integridad Relacional y Restricciones}
Se ejecutó un set de pruebas de inserción y transacciones concurrentes demostrando el cumplimiento de las restricciones \texttt{CHECK} de ponderaciones ($0.00 \leq \text{ponderacion} \leq 100.00$) y el bloqueo de firmas duplicadas para el mismo escalón jerárquico.

\subsection{Conclusiones y Recomendaciones Técnicas}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item La persistencia en PostgreSQL 16 vía EF Core 9 provee tipado estricto y total desacoplamiento entre el modelo de dominio y la base de datos física.
    \item Los índices únicos garantizan la estricta integridad de la máquina de estados y del circuito de firmas sin depender exclusivamente de la capa de aplicación.
    \item Mantener la ejecución estricta de migraciones en entornos CI/CD sin modificaciones manuales directas al esquema SQL.
\end{itemize}
