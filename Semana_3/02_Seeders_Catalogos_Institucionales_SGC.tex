\section{Título}
\textbf{Denominación del Entregable:} Datos Iniciales y Catálogos Institucionales SGC (Seeders SQL y Bcrypt en Node.js / PostgreSQL 18) (EDT 3.2)



\section{Introducción}
Para que el sistema \textbf{SIGE} opere en plena correspondencia con el organigrama y normativas de la FISEI UTA, la base de datos relacional debe inicializarse de manera idempotente con los catálogos maestros institucionales, los roles del Sistema de Gestión de Calidad (SGC) y los usuarios acreditados para cada nivel de toma de decisiones. El proceso de sembrado de datos (\textit{Data Seeding}) se articula mediante el script \texttt{backend/src/database/seed.sql} y el módulo de inicialización en Node.js, garantizando que al desplegar los contenedores locales de \textbf{PostgreSQL (18)} se disponga de inmediato de un entorno operativo con credenciales cifradas con \textbf{Bcrypt.js} (cost factor 12).

\section{Objetivo}

\subsection{Objetivo General}
Poblar de forma automatizada e idempotente los datos semilla institucionales en PostgreSQL 18 mediante scripts SQL y utilitarios de cifrado en Node.js + Express (v5), garantizando la disponibilidad inmediata de carreras, roles, usuarios y catálogo SGC para pruebas y auditoría.

\subsection{Objetivos Específicos}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt, topsep=1.5pt]
    \item Configurar la tabla de carreras con la Carrera de Ingeniería de Software de la FISEI.
    \item Registrar los roles oficiales del SGC (\texttt{DOCENTE\_RESPONSABLE}, \texttt{COORD\_AREA\_CONOCIMIENTO}, \texttt{COORD\_CARRERA}, \texttt{ADMINISTRADOR}, \texttt{SUBDECANO}).
    \item Crear usuarios semilla con contraseñas cifradas mediante Bcrypt.js (12 salt rounds) vinculados a sus correos institucionales \texttt{@uta.edu.ec}.
    \item Inyectar el catálogo maestro de 15 actividades tipo SGC para optimizar el autocompletado en el Wizard de Matriz.
\end{itemize}

\section{Alcance}

\subsection{Alcance Incluido}

\subsection{Límites y Exclusiones}
No reemplaza la sincronización futura con el directorio activo institucional LDAP.

\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt, topsep=2pt]
    \item \textbf{Data Seeding:} Inserción controlada de datos estáticos o predeterminados necesarios para el arranque operativo del sistema.
    \item \textbf{Idempotencia:} Propiedad por la cual una operación produce el mismo resultado sin importar cuántas veces se ejecute (\texttt{ON CONFLICT DO NOTHING}).
\end{itemize}

\section{Método, Políticas y Contenidos}
Invocación en el ciclo de vida de la aplicación WebAPI mediante \texttt{IServiceScope} al iniciar el contenedor. Se definen políticas estrictas: ninguna contraseña semilla se almacena en texto plano, implementando hashing criptográfico seguro (BCrypt/PBKDF2 con sal). La ejecución es estrictamente idempotente mediante cláusulas condicionales de existencia previa.
