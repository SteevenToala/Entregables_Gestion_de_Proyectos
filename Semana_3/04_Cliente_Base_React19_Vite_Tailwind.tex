\textbf{Denominación del Entregable:} Configuración del Cliente Web Base: React + Vite, Tailwind CSS + CSS Keyframes, Sistema de Navegación, Interceptor de Auto-Renovación Axios y Contexto de Autenticación



% =============================================================
% 2. INTRODUCCIÓN
% =============================================================
\section{Introducción}
La interfaz de usuario del sistema \textbf{SIGE} debe ofrecer una experiencia visual contemporánea, fluida, reactiva y plenamente adaptativa para los docentes, revisores de área, coordinadores de carrera y autoridades de la FISEI. Para lograr tiempos de carga imperceptibles (arranque en milisegundos con Vite ESM), modularidad de componentes y animaciones aceleradas por hardware (GPU), se adoptó la arquitectura de cliente basada en \textbf{React + Vite} y un sistema de estilos con \textbf{Tailwind CSS + CSS Keyframes}.

Este entregable formaliza la construcción de la estructura \texttt{frontend/} dentro del repositorio monorepo \texttt{SIGE/}, la configuración del diseño institucional con la paleta oficial (\textbf{Azul UTA/FISEI \#00345E}), la implementación del gestor global de estado de autenticación \texttt{AuthContext.jsx}, el enrutador protegido por roles institucionales y el cliente HTTP Axios con interceptores avanzados para auto-renovación silenciosa de Access Tokens mediante Refresh Tokens.

% =============================================================
% 3. OBJETIVO
% =============================================================
\section{Objetivo}

\subsection{Objetivo General}
Construir la arquitectura base del cliente frontend en React y Vite dentro de la estructura monorepo \texttt{SIGE/frontend/}, estableciendo el sistema de componentes visuales con Tailwind CSS y CSS Keyframes, el enrutamiento protegido por RBAC y la capa de consumo HTTP con auto-renovación de credenciales.

\subsection{Objetivos Específicos}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt, topsep=1.5pt]
    \item Configurar el entorno de desarrollo con Vite asegurando recarga en caliente instantánea (\textit{Hot Module Replacement - HMR}) y compilación optimizada para producción.
    \item Implementar en \texttt{tailwind.config.js} e \texttt{index.css} el sistema de diseño institucional con la paleta de colores UTA/FISEI (\texttt{\#00345E}), componentes con glassmorphism y microanimaciones fluidas por GPU.
    \item Desarrollar el interceptor HTTP de Axios en \texttt{frontend/src/api/client.js} con inyección de cabeceras Bearer y auto-renovación ante respuestas 401 Unauthorized.
    \item Construir las páginas fundamentales \texttt{LoginPage.jsx} (autenticación institucional) y \texttt{DashboardPage.jsx} (panel principal según rol).
\end{itemize}

\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt, topsep=2pt]
    \item \textbf{Vite:} Herramienta de compilación frontend basada en Rollup y esbuild que aprovecha módulos ES nativos para máxima velocidad.
    \item \textbf{Tailwind CSS:} Framework CSS utilitario para composición atómica y responsive de interfaces sin sobrecarga de estilos redundantes.
    \item \textbf{CSS Keyframes:} Reglas de animación ejecutadas directamente en GPU que garantizan 60 FPS estables.
    \item \textbf{Axios Interceptor:} Capa intermedia que manipula peticiones o respuestas HTTP de forma centralizada.
    \item \textbf{EDT (\textit{Estructura de Desglose del Trabajo}):} Descomposición funcional jerárquica del proyecto.
\end{itemize}

\section{Método, Políticas y Contenidos}
Desarrollo basado en arquitectura modular de componentes funcionales en React con Hooks nativos y enrutamiento con \texttt{react-router-dom}. Se establecen políticas rigurosas:
\begin{enumerate}[leftmargin=1.5em, itemsep=1.5pt]
    \item \textbf{Identidad Visual Estricta:} Uso obligatorio de la paleta institucional centrada en \texttt{\#00345E}.
    \item \textbf{Animaciones por GPU:} Las transiciones de interfaz emplean \texttt{transform} y \texttt{opacity} en CSS Keyframes.
    \item \textbf{Cliente HTTP Centralizado:} Prohibido el uso directo de \texttt{fetch()}; todas las llamadas deben utilizar la instancia configurada de Axios.
\end{enumerate}

\subsection{Interceptor Axios de Auto-Renovación (client.js)}
\begin{lstlisting}[language=Java]
// frontend/src/api/client.js
import axios from 'axios';

const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:5000/api',
});

api.interceptors.request.use((config) => {
  const token = localStorage.getItem('sige_access_token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

api.interceptors.response.use(
  (res) => res,
  async (error) => {
    const orig = error.config;
    if (error.response?.status === 401 && !orig._retry) {
      orig._retry = true;
      try {
        const refreshToken = localStorage.getItem('sige_refresh_token');
        const { data } = await axios.post(`${api.defaults.baseURL}/auth/refresh`, { refreshToken });
        localStorage.setItem('sige_access_token', data.data.accessToken);
        orig.headers.Authorization = `Bearer ${data.data.accessToken}`;
        return api(orig);
      } catch (err) {
        localStorage.clear();
        window.location.href = '/login';
        return Promise.reject(err);
      }
    }
    return Promise.reject(error);
  }
);
export default api;
\end{lstlisting}
