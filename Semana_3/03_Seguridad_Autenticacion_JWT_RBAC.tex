\section{Título}
\textbf{Denominación del Entregable:} Módulo de Seguridad: Autenticación Basada en Tokens JWT, Criptografía Bcrypt.js, Blindaje HTTP Helmet y Control de Acceso RBAC (Node.js + Express v5 API REST)



% =============================================================
% 2. INTRODUCCIÓN
% =============================================================
\section{Introducción}
La confidencialidad, trazabilidad y control de privilegios en el sistema \textbf{SIGE} exigen una arquitectura de seguridad robusta y sin estado (\textit{stateless}). Dado que los docentes redactan información sensible y las autoridades emiten dictámenes oficiales con valor legal institucional bajo normas ISO 9001:2015, la autenticación debe impedir accesos indebidos, ataques de fuerza bruta y garantizar el principio de no repudio.

El estándar \textbf{JSON Web Tokens (JWT)} con firma criptográfica HMAC-SHA256, el hashing adaptativo de contraseñas con \textbf{Bcrypt.js} (coste 12 salt rounds), la protección de cabeceras HTTP mediante \textbf{Helmet} y el modelo de \textbf{Control de Acceso Basado en Roles (RBAC)} implementado en middlewares modulares de \textbf{Node.js + Express (v5)} permiten autenticar solicitudes HTTP de forma desacoplada, transportar claims seguros (identificador único UUID, correo institucional, rol institucional y unidad académica) y autorizar endpoints mediante validación estricta de políticas operativas.

% =============================================================
% 3. OBJETIVO
% =============================================================
\section{Objetivo}

\subsection{Objetivo General}
Desarrollar el módulo de autenticación y autorización en la capa de Backend API REST de SIGE utilizando Node.js, Express (v5), PostgreSQL (18), Bcrypt.js, JWT y Helmet, blindando los endpoints contra accesos no autorizados y asegurando la segregación estricta de funciones según los roles de la FISEI.

\subsection{Objetivos Específicos}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt, topsep=1.5pt]
    \item Implementar el hashing seguro de credenciales con \texttt{bcryptjs} utilizando un factor de costo de 12 salt rounds tanto en la siembra inicial como en los servicios de autenticación.
    \item Configurar la generación de pares de tokens en \texttt{token.util.js}: Access Token de corta duración (15--30 minutos) firmado con clave simétrica secreta HMAC-SHA256 y Refresh Token persistente en PostgreSQL 18 (7 días) para rotación segura.
    \item Desarrollar los middlewares modulares de seguridad en Express (v5): \texttt{auth.middleware.js} para verificación Bearer y control RBAC, \texttt{rateLimiter.middleware.js} para prevención de abusos DoS y \texttt{helmet} para inyección de cabeceras defensivas.
    \item Implementar el controlador modular \texttt{auth.controller.js} y el servicio \texttt{auth.service.js} con endpoints \texttt{/api/auth/login}, \texttt{/api/auth/refresh}, \texttt{/api/auth/logout} y \texttt{/api/auth/me}.
\end{itemize}

% =============================================================
% 4. ALCANCE
% =============================================================
\section{Alcance}

\subsection{Alcance Incluido}
Generación y verificación de tokens JWT firmados con expiración configurable (\texttt{JWT\_EXPIRES\_IN=15m}, \texttt{REFRESH\_TOKEN\_EXPIRES\_IN=7d}), claims de identidad obligatorios (\texttt{sub}, \texttt{email}, \texttt{role}, \texttt{carreraId}, \texttt{nombreCompleto}), middleware global \texttt{authenticateToken}, middleware \texttt{authorizeRoles}, almacenamiento y rotación de Refresh Tokens en PostgreSQL 18 y blindaje HTTP con Helmet.

\subsection{Límites y Exclusiones}
No incluye autenticación federada externa con OAuth2/SAML de Google Workspace UTA ni autenticación multifactor biométrica en esta versión.

\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt, topsep=2pt]
    \item \textbf{JWT (JSON Web Token):} Estándar abierto (RFC 7519) para transmitir información estructurada, compacta y verificable criptográficamente.
    \item \textbf{Bcrypt.js:} Algoritmo de derivación de clave adaptativo y hashing de contraseñas con salting aleatorio resistente a ataques por GPU.
    \item \textbf{Helmet:} Colección de middlewares para Express que inyecta y configura 11 cabeceras HTTP de protección defensiva.
    \item \textbf{RBAC (Role-Based Access Control):} Mecanismo de restricción de accesos donde los permisos se asignan a roles institucionales definidos.
    \item \textbf{EDT (\textit{Estructura de Desglose del Trabajo}):} Descomposición funcional y jerárquica del proyecto.
\end{itemize}

% 8. MÉTODO, POLÍTICAS Y CONTENIDOS
% =============================================================
\section{Método, Políticas y Contenidos}
Se aplica una arquitectura modular desacoplada en Node.js y Express (v5) con PostgreSQL 18. Se establecen políticas rigurosas de seguridad:
\begin{enumerate}[leftmargin=1.5em, itemsep=1.5pt]
    \item \textbf{Confidencialidad del Token:} Se prohíbe transportar contraseñas o hashes dentro del payload del JWT.
    \item \textbf{Tiempo de Vida Efímero:} El Access Token expira en 15 minutos; el Refresh Token en 7 días y sufre rotación de uso único.
    \item \textbf{Denegación por Defecto:} Todo endpoint requiere autenticación Bearer a menos que sea explícitamente público.
    \item \textbf{Blindaje HTTP:} Helmet inyecta cabeceras como X-Frame-Options, X-Content-Type-Options y HSTS.
\end{enumerate}

\section{Descripción de actividades}

\subsection{Implementación de Utilidades de Seguridad}
En \texttt{backend/src/utils/token.util.js} y \texttt{password.util.js} se encapsula el hashing con Bcrypt.js y la firma con JWT:

\begin{lstlisting}[language=Java]
// backend/src/utils/password.util.js
import bcrypt from 'bcryptjs';
const SALT_ROUNDS = 12;

export const hashPassword = async (plainPassword) => {
  return await bcrypt.hash(plainPassword, SALT_ROUNDS);
};

export const comparePassword = async (plainPassword, hashedPassword) => {
  return await bcrypt.compare(plainPassword, hashedPassword);
};
\end{lstlisting}

\subsection{Middlewares de Autenticación y Autorización RBAC}
En \texttt{backend/src/middlewares/auth.middleware.js} se interceptan las solicitudes entrantes:

\begin{lstlisting}[language=Java]
// backend/src/middlewares/auth.middleware.js
import jwt from 'jsonwebtoken';

export const authenticateToken = (req, res, next) => {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1];
  if (!token) return res.status(401).json({ success: false, message: 'Token no proporcionado' });

  jwt.verify(token, process.env.JWT_SECRET, (err, user) => {
    if (err) return res.status(401).json({ success: false, message: 'Token invalido o expirado' });
    req.user = user;
    next();
  });
};

export const authorizeRoles = (...allowedRoles) => {
  return (req, res, next) => {
    if (!req.user || !allowedRoles.includes(req.user.role)) {
      return res.status(403).json({ success: false, message: 'Acceso denegado: Privilegios insuficientes' });
    }
    next();
  };
};
\end{lstlisting}

\subsection{Matriz de Autorización RBAC en Endpoints de SIGE}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item \texttt{POST /api/auth/login}: Público (autenticación y entrega de Access/Refresh tokens).
    \item \texttt{POST /api/auth/refresh}: Público (rotación de Access Token mediante Refresh Token).
    \item \texttt{GET /api/auth/me}: Autenticado (\texttt{*} -- cualquier usuario con token válido).
    \item \texttt{POST /api/documentos}: Restringido a \texttt{DOCENTE\_RESPONSABLE}.
    \item \texttt{POST /api/revisiones/dictamen}: Restringido a \texttt{COORD\_AREA\_CONOCIMIENTO}, \texttt{COORD\_CARRERA}, \texttt{SUBDECANO}.
    \item \texttt{POST /api/administracion/usuarios}: Restringido exclusivamente a \texttt{ADMINISTRADOR}.
\end{itemize}

\subsection{Conclusiones y Recomendaciones Técnicas}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item El esquema JWT + RBAC otorga desacoplamiento total entre el cliente frontend React + Vite y la API REST Express (v5).
    \item Los roles modelados corresponden de forma unívoca a la estructura académica del SGC de la FISEI UTA.
    \item Configurar HTTPS con certificados SSL/TLS y cabeceras estrictas HSTS en producción para evitar cualquier intercepción de tráfico.
\end{itemize}

\subsection*{Anexo 2: Matriz de Códigos de Retorno HTTP de Seguridad}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item \texttt{200 OK}: Autenticación exitosa, entrega de tokens o perfil recuperado.
    \item \texttt{401 Unauthorized}: Token ausente, firma inválida o expirado.
    \item \texttt{403 Forbidden}: Token válido pero rol o privilegios insuficientes en RBAC.
    \item \texttt{429 Too Many Requests}: Tasa de peticiones excedida (protección rate limiter).
    \item \texttt{500 Internal Server Error}: Excepción no controlada gestionada por el middleware centralizado.
\end{itemize}
