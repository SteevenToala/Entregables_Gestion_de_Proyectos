\section{Introducción}
La confidencialidad, trazabilidad y control de privilegios en el sistema \textbf{SIGE} exigen una arquitectura de seguridad robusta y sin estado (*stateless*). Dado que los docentes redactan información sensible y las autoridades emiten dictámenes oficiales con valor legal, la autenticación debe impedir accesos indebidos y garantizar el no repudio.

El estándar **JSON Web Tokens (JWT)** junto con el modelo de **Control de Acceso Basado en Roles (RBAC)** implementado en ASP.NET Core 9 permite autenticar solicitudes HTTP, transportar claims seguros (identificador de usuario, rol institucional y carrera asignada) y autorizar endpoints mediante políticas estrictas y atributos \texttt{[Authorize(Roles = "...")]}.

\section{Objetivo}

\subsection{Objetivo General}
Desarrollar el módulo de autenticación y autorización en la capa WebAPI de SIGE utilizando JWT y RBAC, blindando los endpoints contra accesos no autorizados y asegurando la segregación de funciones según los roles de la FISEI.

\subsection{Objetivos Específicos}
\begin{itemize}[leftmargin=1.5em, itemsep=1.5pt, topsep=1.5pt]
    \item Configurar el middleware de autenticación \texttt{JwtBearer} con firma simétrica HMAC-SHA256 y validación estricta de emisor (*Issuer*), audiencia (*Audience*) y tiempo de vida (*Lifetime*).
    \item Implementar el controlador \texttt{AuthController} con endpoints para inicio de sesión (\texttt{/api/auth/login}) y perfil de usuario autenticado (\texttt{/api/auth/me}).
    \item Definir políticas de autorización RBAC para restringir acciones críticas (dictámenes, habilitación extemporánea y circuito de firmas).
\end{itemize}

\section{Alcance}

\subsection{Alcance Incluido}
Generación de token JWT firmado con expiración de 120 minutos, claims de identidad (\texttt{sub}, \texttt{email}, \texttt{role}, \texttt{carrera\_id}, \texttt{nombre\_completo}), middleware global de captura de token en cabecera \texttt{Authorization: Bearer <token>} y pruebas de seguridad.

\subsection{Límites y Exclusiones}
No incluye autenticación federada externa con OAuth2 de Google Workspace en esta iteración.

\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt, topsep=2pt]
    \item \textbf{JWT (JSON Web Token):} Estándar abierto (RFC 7519) para transmitir información segura entre partes en formato JSON.
    \item \textbf{RBAC (Role-Based Access Control):} Mecanismo de restricción de accesos basado en las responsabilidades institucionales.
\end{itemize}

\section{Método, Políticas y Contenidos}
Implementación basada en Microsoft ASP.NET Core Identity y Microsoft.AspNetCore.Authentication.JwtBearer. Se establecen políticas rigurosas de seguridad: se prohíbe transportar credenciales o hashes dentro del token JWT, se exige clave simétrica de 256 bits y se devuelven códigos HTTP 401 Unauthorized o 403 Forbidden según corresponda para peticiones no válidas.

\section{Descripción de actividades}

\subsection{Estructura del Payload JWT Generado}
Los tokens emitidos tras la autenticación exitosa contienen las declaraciones necesarias para la toma de decisiones descentralizada:
\begin{verbatim}
{
  "sub": "b1eebc99-9c0b-4ef8-bb6d-6bb9bd380b22",
  "email": "docente.software@uta.edu.ec",
  "role": "DOCENTE_RESPONSABLE",
  "carrera_id": "a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11",
  "nbf": 1726315200,
  "exp": 1726322400,
  "iss": "SIGE-UTA-AuthServer",
  "aud": "SIGE-ClientApp"
}
\end{verbatim}

\subsection{Endpoint /api/auth/login y Control de Acceso RBAC}
Se implementó el controlador \texttt{AuthController} validando contraseñas mediante hash con sal y protegiendo las rutas con el atributo \texttt{[Authorize(Roles = "...")]}.

\subsection{Matriz de Autorización RBAC en Endpoints}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item \texttt{POST /api/documentos}: Restringido a \texttt{DOCENTE\_RESPONSABLE}.
    \item \texttt{POST /api/revisiones/dictamen}: Restringido a autoridades evaluadoras.
    \item \texttt{POST /api/administracion/habilitaciones}: Exclusivo para \texttt{ADMINISTRADOR}.
\end{itemize}

\subsection{Conclusiones y Recomendaciones Técnicas}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item El esquema JWT + RBAC otorga desacoplamiento total entre el cliente frontend y la WebAPI, garantizando transacciones seguras y trazables.
    \item Los roles modelados corresponden de forma unívoca a la estructura académica del SGC de la FISEI UTA.
    \item Configurar HTTPS estricto con certificados SSL en ambientes de producción para evitar la intercepción del token en tránsito.
\end{itemize}
