\section{Introducción}
La arquitectura de software del sistema \textbf{SIGE} se concibe bajo principios de alta cohesión, bajo acoplamiento, escalabilidad e independencia de frameworks. Se implementa una \textbf{Arquitectura Limpia (Clean Architecture)} en capas concéntricas sobre \textbf{.NET 9}, complementada con el \textbf{Modelo C4} para la visualización estructural del sistema y especificaciones rigurosas de seguridad basadas en JSON Web Tokens (JWT) y Control de Acceso Basado en Roles (RBAC).

\section{Objetivo}

\subsection{Objetivo General}
Diseñar y formalizar la arquitectura de software del sistema SIGE mediante Clean Architecture y el Modelo C4, asegurando mantenibilidad, testabilidad y privacidad de datos.

\subsection{Objetivos Específicos}

    \item Formalizar los mecanismos de seguridad criptográfica del token JWT.
\end{enumerate}

\section{Definiciones}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item \textbf{Clean Architecture:} Enfoque arquitectónico que prioriza la lógica de dominio sobre los frameworks y bases de datos.
    \item \textbf{Modelo C4:} Marco de trabajo para la diagramación de arquitectura en cuatro niveles jerárquicos (Contexto, Contenedores, Componentes, Código).
    \item \textbf{CQRS:} Patrón de segregación de responsabilidades de comandos (escritura) y consultas (lectura).
    \item \textbf{JWT (\textit{JSON Web Token}):} Estándar abierto (RFC 7519) para transmitir información de identidad de forma segura.
\end{itemize}

\section{Método, Políticas y Contenidos}

\subsection{Capas de Clean Architecture (.NET 9)}
Para asegurar alta mantenibilidad, independencia de frameworks, bajo acoplamiento y testabilidad rigurosa, el backend de \textbf{SIGE} se estructura bajo el patrón \textbf{Clean Architecture (Arquitectura Limpia)} en .NET 9:

\begin{enumerate}[leftmargin=1.5em, itemsep=2pt]
    \item \textbf{Capa de Dominio (\texttt{SIGE.Domain}):} Entidades nucleares (\texttt{Documento}, \texttt{ActividadMatriz}, \texttt{FirmaLegalizacion}, \texttt{EvidenciaMinio}), Value Objects, Enums institucionales (\texttt{EstadoDocumento}, \texttt{TipoInforme}) y Domain Events.
    \item \textbf{Capa de Aplicación (\texttt{SIGE.Application}):} Casos de uso estructurados mediante CQRS (Commands/Queries con MediatR), DTOs, contratos de interfaces y validadores deterministas con FluentValidation.
    \item \textbf{Capa de Infraestructura (\texttt{SIGE.Infrastructure}):} DbContext de Entity Framework Core para PostgreSQL 16, repositorio cliente de MinIO S3, cliente HTTP para LanguageTool y motor QuestPDF / OpenXML.
    \item \textbf{Capa de Presentación / WebAPI (\texttt{SIGE.WebAPI}):} Controladores RESTful, middlewares de autenticación JWT y RBAC, Swagger OpenAPI y configuración de arranque (\texttt{Program.cs}).
\end{enumerate}

    \item \textbf{Asistente Semántico IA:} Inferencia delegada a Google Gemini API (Gemini 2.5 Flash / Google AI) mediante peticiones seguras HTTPS sin costos de suscripción ni sobrecarga de GPU local.
    \item \textbf{Motor de Documentos:} QuestPDF y OpenXML para renderizado fidedigno de PDF y Word \texttt{.docx}.
\end{itemize}

\subsection{Patrones de Diseño Implementados}
\begin{enumerate}[leftmargin=1.5em, itemsep=2.5pt]
    \item \textbf{Repository \& Unit of Work:} Desacopla la persistencia de datos y garantiza transacciones ACID en operaciones complejas (ej. cambio de estado + registro de auditoría + incremento de versión).
    \item \textbf{CQRS con MediatR:} Separa las operaciones de lectura (\textit{Queries}) de las operaciones de escritura/mutación (\textit{Commands}).
    \item \textbf{Pipeline Behaviors (Validation Gate):} Middleware de MediatR que intercepta cada \textit{Command} y ejecuta automáticamente las reglas de FluentValidation antes de llegar a la capa de datos.
    \item \textbf{Adapter Pattern para MinIO:} Interfaz \texttt{IObjectStorageService} que aísla la lógica del SDK de MinIO/S3.
    \item \textbf{Factory Pattern para Exportación:} Generador dinámico que decide si renderizar en formato PDF (QuestPDF) o formato Word (OpenXML) según la solicitud institucional.
\end{enumerate}

\subsection{Especificación de Seguridad y Token JWT}
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item \textbf{Algoritmo de Firma Criptográfica:} HMAC-SHA256 con clave simétrica de 512 bits almacenada en variables de entorno seguras.
    \item \textbf{Tiempo de Expiración:} Access Token de corta duración (30 minutos) junto a un Refresh Token seguro de 7 días almacenado en base de datos con revocación automática.
    \item \textbf{Claims Oficiales en el Token:}
    \begin{itemize}[leftmargin=1.2em, itemsep=1pt]
        \item \texttt{sub (UserId):} Identificador único universal del usuario (UUID).
        \item \texttt{email:} Correo electrónico institucional (\texttt{@uta.edu.ec}).
        \item \texttt{fullName:} Nombre completo del docente o directivo.
        \item \texttt{role:} Rol RBAC (\texttt{DocenteElaborador}, \texttt{CoordArea}, \texttt{CoordCarrera}, \texttt{Admin}).
        \item \texttt{facultadId} y \texttt{carreraId:} Pertenencia institucional a la FISEI e Ingeniería de Software.
    \end{itemize}
\end{itemize}
